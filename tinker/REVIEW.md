# 折腾志 · 每日复盘

每次运行往下追加一条。这个文件的作用是让后来的每一次运行都能看到前面几次
试过什么、判断错过什么，从而不必重复踩同一个坑。可以质疑这里的任何结论。

格式：

```
## YYYY-MM-DD
抓取 N 条 → 规则入围 M 条 → 收录 K 条（收录率 K/M）
来源分布：...
毙掉的主要类型：...
本次改动：...
```

## 2026-08-01（四稿 · 拆分「工具」与「话题」）

用户问：「所谓按工具，Claude Code 和 Codex 以及 OpenClaw 是工具，但 MCP、CLAUDE.md、
Vibe Coding、Agent Skills、规格驱动开发，这些不能算是工具吧」。他是对的，
而且 `vocab.mjs` 里那段概念的注释本来就写着「生态概念：不是工具」——
我知道它们不是工具，却把两段塞进了同一个叫「按工具」的筛选器。标签在骗人。

改动：

1. 词表拆成 `TOOLS`（产品，51 个）和 `TOPICS`（概念/实践，12 个）。
   判据是「能不能安装、能不能打开」。打分时两者等价（标题出现 MCP 和出现 Cursor
   一样说明这篇在讲 agent），但页面上是两组独立筛选器，可以叠加。
   条目上工具用实线框、话题用虚线加方括号，视觉上也分开。
2. **补上语料里出现但词表没有的产品**：OpenClaw、Hermes、NanoClaw、Kimi Code、
   Claude Cowork、Claudian。用户提到 OpenClaw 时我才发现它根本不在表里。
   同时补了话题 Loop Engineering（语料里出现 31 次）、Context Engineering、Agent 记忆、Hooks。
3. **修掉一个中文别名的误判**：「心流」是 iFlow 的别名，命中了「核**心流**程」，
   于是 TonyBai 那篇 TabQueue 被打上 iFlow 标签。同类的还有「扣子」（Coze）会命中「纽扣子」。
   ASCII 词边界规则对中文完全无效，因为中文本来就不分词。
   结论写进代码注释：**两个字的中文别名基本都会误伤，别加**。

发现路径值得记一笔：这个 bug 是用户盯着页面上一个看起来不对的标签问出来的，
不是测试或统计发现的。分类维度错了不会报错，只会让人觉得「这个筛选器怪怪的」。

## 2026-08-01（三稿 · 扩源）

**上一稿只治了症状。** 二稿把及格线提到 4 分确实清掉了水货，但没回答一个更根本的问题：
为什么名单里非得有那么多论坛帖？答案是**源的成分本身就不对**——
67 个源里博客只贡献了 110/445 条，且大半月更，名单只能靠 V2EX 撑。

做法：不再靠搜索引擎找博客（搜出来全是 CSDN/知乎这类 SEO 平台页，试过，无效），
改从 timqian/chinese-independent-blogs 这个社区索引入手（1465 个中文独立博客，全带 RSS）。
新写了 `scripts/tinker-harvest.mjs`，**用数据选源**而不是人工猜：
把技术标签的候选 feed 全抓一遍，只留 120 天内活跃、且近 20 篇里 ≥3 篇真命中 agent 词表的。
筛出 84 个，源从 67 涨到 151。

效果（seen.json 已记录旧条目，所以这批是干净的增量对照）：
新增 191 条 → 入围 19 条，来自 **16 个不同博客，V2EX 零条**。
标题质量肉眼可见地不同：「我的 AI 助手疯了，30 分钟停不下来」
「借鉴 Herdr 让 Claude 从头到尾写出一个 tmux AI Agent 监控器」
「把 Obsidian 当 AI 时代的 IDE」「AI 写标书踩过的那些坑」。
并入本期后共 31 篇，V2EX 占比从约一半降到 8/31，来源从 11 个源变成 21 个。

**顺带修掉一个影响面很大的 bug**：`&amp;` 这个 HTML 实体会被判成命中工具 Amp。
前后都不是拉丁字母，词边界规则拦不住。feed 正文里 `&amp;` 遍地都是，
所以每篇带它的文章都白拿了一次工具命中分。第一次跑扩源脚本时，
上百个从没写过 agent 的博客被判成「写过 Amp」，才发现这件事。
修法是在边界判断里单独排除 `&` 前缀。

抓取耗时：151 个源、并发 10，2 分 34 秒，和之前 67 个源差不多，说明瓶颈在慢源不在数量。

待观察：
- 新增的 84 个源里必然有一批长期零产出，21 天后按 REVIEW 流程点名清理
- 阈值定在「近 20 篇 ≥3 篇命中」是拍的，可以调 `--min-hits` 重跑看看 2 篇会多出多少噪声

## 2026-08-01（二稿）

抓取 445 条 → 规则入围 37 条 → 收录 17 条（收录率 46%）

**一稿收了 29 篇，用户看完的反馈是「V2EX 那种质量太差了」，改掉重发。**
诊断下来主因不在规则漏了，在编辑门槛太低：29 篇里 13 篇是 3 分，
而那 13 篇几乎全是论坛的产品自荐帖和短讨论帖。两处一起改：

- **规则**：新增自荐帖识别（求 Star / 欢迎试用 / 开发者自荐 / 送会员 / 求交流，扣 6 分），
  论坛与搜索源加篇幅项（<600 字符扣 3，≥1800 加 1）。
  长度只做减分不做门槛——「用 Claude Code 抢注游戏 wiki 站」只有 529 字符却是当天最好的一篇。
  这一改清掉了 memU×2、Somvia、pi2.nvim、OpenMarkdown、[送会员] 等 8 条。
- **编辑**：及格线从 3 分提到 4 分，写进 TINKER_DAILY.md。宁可某天只有 3 篇，不用 3 分的凑数。

**已知误伤**：「大家用 Claude Code / Codex 攒了几个月的经验，最后都去哪了？」
529 字符 + 问号结尾，同时吃到短帖和疑问帖两项扣分被规则毙掉，但它其实是当天最好的讨论之一。
短论坛帖里的好东西和提问帖用规则很难分开，暂时接受这个代价，后续观察是不是频繁发生。

### 一稿数据（保留作对照）

抓取 445 条 → 规则入围 42 条 → 收录 29 条（收录率 69%）

来源分布：V2EX 搜索 24、TonyBai 5、小众软件论坛搜索 3、掘金搜索 2、宝玉xp 2，
其余 6 个源各 1。这是首次运行，回溯了 21 天窗口，所以量偏大；之后每天只会有增量。

毙掉的主要类型：产品自荐（memU、VideoFlow、RaisDB、PublishPort，共 5 篇——
都是「我做了个东西，欢迎试用」，没有作者用它解决自己问题的过程）、
带中转站推广的教程软文 2 篇、纯新闻 1 篇（MCP 协议更新播报）、
无内容的求助帖 3 篇、第三方转述型软件推荐 2 篇。

本次改动（都是第一版规则跑完后发现问题才改的）：

1. **按源配额**。第一版只按总分排序取前 60，结果 V2EX 一家占 31 席。
   论坛长帖天然堆满「我」「折腾」「踩坑」这些经验词，分数虚高，
   把 TonyBai「我让 AI 帮我做了个浏览器插件」这类正中靶心的博客文挤出了名单。
   改成先按源配额（8 席）切一刀，再按分数补齐。
2. **短工具名必须按词边界匹配**。`dia` 命中了 "ASCII diagram"，`amp` 命中了 "example"，
   于是一篇讲字体对齐的文章和一篇 Spring Boot 排错笔记被判成 agent 实践。
   中文没有空格所以不能用 `\b`，改成要求紧邻字符不是拉丁字母或数字。
3. **招聘帖硬毙**。V2EX 和 Ruby China 的 JD 必写「AI Agent」，百分百命中工具词。
   用薪资数字（`\d+K-\d+K`、`\d+W-\d+W`）做判据最可靠。
4. **「我+动作」句式加权**。实测这是个人折腾最强的语言指纹，
   比任何单个经验词都准，几乎不出现在新闻稿和软文里。
5. **探测器 bug**：`type=application/rss+xml` 不带引号时匹配不到，
   漏掉了黑暗執行緒这类手写模板的站点。

  论坛，值得再想办法（目前只有 `latest.rss` 在浏览器 UA 下偶尔能通）。
- ~~微信公众号完全没有覆盖，wechat2rss 值得试。~~ **已调查，是死路**：
  wechat2rss.xlab.app 的免费列表共 395 个公众号，其中 326 个是安全类，
  开发类只有 12 个（腾讯技术工程、阿里技术、机器之心这类），
  宝玉、卡兹克、归藏、赛博禅心等真正写 agent 实践的一个都不在。
  公众号这块要覆盖只能自建 wechat2rss 实例并逐个添加账号，成本远高于收益，暂不做。
